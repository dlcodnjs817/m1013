## 1. 방법 — 이번에는 커널로 열었다

09-06 은 STEP 을 정규식으로 파싱하고 STL 정점을 세어 검증했다. 그 방식은 **엔티티는 보이지만
솔리드는 안 보인다.** 이번에 `cadquery` 가 환경에 있는 것을 확인하고 B-rep 로 다시 읽었다.

바로 드러난 것: SMC STEP 은 솔리드가 **3개**다.

```
solid0  몸체        Y -28.30 ..   0.00   Z ±71.0    체적 158,930 mm^3
solid1  블록 (Z+)   Y -33.00 .. -18.40   Z -21.8 .. 71.4
solid2  블록 (Z-)   Y -33.00 .. -18.40   Z -71.4 .. 21.8
```

**장착면 = 몸체 Y=0** 이 이걸로 확정됐다. 다월 구멍(깊이 3)과 배면 M5 암나사가 둘 다 이 면에서
시작하고, 반대편(Y=-28.3)에는 Ø7.5 릴리프만 뚫려 있다. 09-06 이 정규식으로 본
"Ø7.5 카운터보어 8.3 深" 은 **반대쪽 면의 릴리프**였고, 나사는 장착면 바로 아래에서 시작한다.

또 하나 — **배포 STEP 은 조가 완전 열린 상태**다 (블록 바깥 끝 ±71.4). 09-06 이 본
`Ø3.242 @ Z=6.7 / 32.7` 은 솔리드에 속하지 않는 잔여 형상이었고, 실제 M4 는 `Z=±38.7 / ±64.7` 이다.
바깥 끝 기준으로는 6.7 / 32.7 로 같으므로 **핑거 구멍 위치는 영향 없다.**

### 좌표 변환

```
flange_X = SMC_Z        flange_Y = -SMC_X        flange_Z = 12 - SMC_Y
```

검산: 그리퍼 측면 M5 가 **flange z = 32** 로 떨어진다 = 밸브·손목캠 브래킷 구멍 높이와 동일.
몸체 z 12~40.3 / 블록 z 30.4~45 = npz `body_z [0.012, 0.045]` 와 일치.

## 3. 정정 ① — 블록 길이 38.20, 판이 1.2 mm 길었다

09-06 §4.5 는 M4 구멍이 블록 양 끝에서 6.7 씩 대칭이라 보고 `6.7 + 32.7 = 39.40` 을 블록 길이로 삼았다.
**비대칭이다.**

```
DXF 치수 체인 (열림 상태 배면도) :  블록 바깥 끝 -- 6.7 -- M4 -- 26 -- M4 -- 5.5 -- 블록 안쪽 끝
블록 길이 = 6.7 + 26 + 5.5 = 38.20        (STEP 평면 Z=1.2 / Z=39.4 로도 확인)
```

판 43.0 = 39.40 + 립 3.6 이었으므로 **1.2 mm 초과**. 결과:

```
완전 닫힘   그리퍼 자체 블록 틈 2.40 mm  ←  판이 이걸 전부 먹어 판 간격 0.00
            즉 그리퍼 내부 스톱이 아니라 우리 판끼리가 스톱이 된다
```

35 mm 큐브를 물 때는 판이 1.5 mm 떨어져 있어 실사용엔 무해하지만, 빈 손 완전 닫힘에서
알루미늄끼리 맞닿는다. **판 41.8 = 38.20 + 3.6 으로 수정** (§6).

수정 후 재검증: 판 간격 **2.40 mm**, 간섭 0, 볼트·립·조·닫힘 갭 33.50 전부 불변.
판이 블록에 전부 받쳐지므로(종전엔 1.2 mm 가 허공) 강성은 오히려 개선.

## 3-1. 정정 ② — 배면 Ø4 는 2개, 한쪽이 장공

09-06 이 "🔴 발주 전 실물 확인" 1번으로 남긴 항목. **해결됐다.**

```
Z = +65.0   원형 Ø4 DP3
Z = -65.0   Ø4 × 5 장공 DP3      (커널: 반원통 2개 @ -65.5 / -64.5 + 평면)
```

원형+슬롯은 2핀 위치결정의 표준 조합이고, **핀 간격 공차가 ±0.5 까지 허용**된다는 뜻이다.
문제의 `127.5` 치수도 정체가 나왔다 — 원형 구멍 중심에서 장공 끝까지이며, 체인이
`6 + 127.5 + 5 + 3.5 = 142` 로 닫히면서 **±65.0 이 맞다는 걸 도면이 스스로 증명**한다.
09-06 의 결론(±65.0)은 옳았고, 근거가 이제 확실해졌다.

## 3-2. 정정 ③ — 착좌 면적

두 C1 모따기 때문에 실제 평면은 Ø31.5~Ø63 이 아니라 **Ø33.5~Ø61 = 2041 mm^2**.
어댑터의 Ø6.6 ×4 + Ø5.8 ×4 가 243 mm^2 를 먹어 **실접촉 1799 mm^2, 손실 11.9%** (09-06 은 4.8%).
볼트 구멍 R21.7~28.3 · 핀하도 R22.1~27.9 는 전부 착좌 환형부(R16.75~30.5) 안이라
**모따기에 걸치는 구멍은 없다.** 1.22 kg 툴에는 여전히 과분한 면적.

## 4. M1013 플랜지 — 제조사 CAD 로 격상

09-06 은 플랜지를 매뉴얼 PDF 900 DPI 픽셀 계측으로 읽었다. 이번에 **`doosan-robot2` 가 휴지통에
있는 것을 발견**해(현재 복구 완료), 두산 배포 메시 `MF1013_6_0.dae` 로 직접 실측했다.

> ⚠️ **함정**: DAE 에 노드 변환 행렬이 걸려 있다 — `translate = (-0.712, -1.363, -26.185)`.
> 정점 좌표를 그대로 읽으면 **플랜지가 26 mm 어긋난다.**

```
link_6 프레임 (z=0 = 플랜지 면)
  z =  0.000   Ø33.5 .. Ø61.0     플랜지 면 (양쪽 C1 모따기 끝)
  z = -1.000   Ø31.5 .. Ø63.0     모따기 바닥 = 보스 실제 지름
  z = -6.495   Ø31.5 .. Ø79.5     보스 밑둥
```

| 항목 | 메시 실측 | 09-06 픽셀 계측 | |
|---|---|---|---|
| Ø63 보스 높이 | **6.495** | 6.5 | ✅ |
| Ø31.5 보어 깊이 | **≥ 6.495** | 6.42 | ✅ |
| 보어 진입 모따기 | **C1** | "C1 모따기" | ✅ |
| 손목 외경 | **Ø89.00** (원통 피팅 잔차 0.0006) | 88.98 | ✅ |

매뉴얼 판독이 전부 맞았다. 스피곳 4 mm 대 보어 6.495 → **여유 2.50 mm**.

**신규 확인 — 플랜지 면이 link_6 원점이다** (메시 z_max = +0.001).
`m1013_kin.py` 가 "EE 프레임 = link_6 = 두산 플랜지" 라고 가정하지만 검증된 적이 없었다.
TCP 83 / 파지점 체인의 기준점은 문제없다.

**신규 지적 — 스피곳 유효 센터링은 3.0 mm.** 보어 입구 1 mm 가 C1 이라 4 mm 중 3 mm 만
진짜 Ø31.5 에 물린다. Ø31.5 에 L/D 0.095 로 충분하고 볼트 4개가 나머지를 잡으므로 그대로 간다.
(늘린다면 5 mm → 유효 4 / 바닥 여유 1.5)

**메시가 못 주는 것**: 두산 시각 메시는 작은 구멍을 전부 생략했다. 플랜지 면에 링 두 개뿐이고
**볼트 구멍이 없다.** 따라서 4-M6 PCD50 탭 위치·깊이(DP6)와 Ø6 H7 위치결정 구멍 각도는
여전히 ISO 9409-1-50-4-M6 + 매뉴얼 근거다. 다만 macro 치수가 전부 일치했으므로 신뢰도는 높다.
핀하도를 0/90/180/270° 네 곳 다 뚫어둔 설계 덕에 위치결정 구멍 각도 관례는 어느 쪽이든 커버된다.

## 5. 미결 — TCP 0.0675 는 기하적으로 불가능

`convert_v6_m1013.py` 의 유도식:

```python
TCP = JAW_TIP + JAW_CLEAR - CUBE_SIZE/2   # 0.083 + 0.002 - 0.0175 = 0.0675
```

`JAW_CLEAR = 2 mm` 는 "조 끝이 상판 위로 2 mm" 라는 뜻인데, **조 38 mm 중 위 8 mm 는 마운트 판**이라
큐브가 들어갈 수 있는 공간은 **30 mm** 뿐이다. 큐브는 35 mm.

```
z=45  블록 밑면 / 조 시작
      +-- 마운트 판 t8 (큐브 진입 불가)
z=53  판 밑면          <- 큐브 윗면의 물리적 한계
      +-- 유효 조 깊이 30 mm
z=83  조 끝 (TCP 83)

큐브 중심 하한 = 53 + 17.5 = 70.5      JAW_CLEAR 하한 = 35 - 30 = 5 mm
```

35 mm 큐브 솔리드를 넣어 검산: 중심 z=67.5 에서 판과 2324 mm^3 관통, **70.5 부터 0**.

**하드웨어 문제가 아니다.** 30 mm 깊이 파지는 충분하고, 조 끝이 상판에서 5 mm 뜨는 건 더 안전하다.
조를 길게 만들어도 이 숫자는 안 변한다 — 큐브 높이를 정하는 건 조 길이가 아니라 **판 밑면**이다.

**영향**: 로봇이 매번 3 mm 더 깊이 내려간다. 폼이라 눌려서 겉보기엔 동작하지만 파지 깊이가
매번 달라지고, 놓을 때도 3 mm 낮다. 놓기 오차 7.8 mm 대비 무시할 크기가 아니다.

**고치는 법**: `JAW_CLEAR = 0.005` → TCP **0.0705**, 재변환(6초). 다만 `v6_staging_tcp0675` 로 돌린
학습이 무효가 되므로 재학습(또는 기존 체크포인트 파인튜닝)이 딸린다. **결정 대기 — 이번 세션 미착수.**
상판 높이 0.4624 는 데이터의 파지 평면에서 유도되므로 **변하지 않는다.**
