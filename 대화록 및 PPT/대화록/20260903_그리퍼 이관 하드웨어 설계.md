## 7. 재변환 — TCP 반영이 모든 것의 선행 조건

### 현재 규약의 문제

```
convert_v6_m1013.py :  TCP = 0.12          (추적점)
prep_replay_ep.py   :  finger_ext F = 0.13883  (추적점 → 큐브 중심)
                    →  현재 플랜지 → 큐브 = 258.8 mm
```

실제 그리퍼는 **83 mm**. 지금 규약대로 실기에 올리면 **핑거 끝이 큐브보다 175.8 mm 위**에 뜬다.

### 수정 식

```python
# convert_v6_m1013.py
# 기존:  p_flange = ac_pos[t] - R @ [0, 0, TCP]            # TCP = 0.12
# 수정:  p_flange = ac_pos[t] + R @ [0, 0, F - TCP_new]
F       = 0.13882972016227912     # replay_ep*.npz 의 finger_ext
TCP_new = 0.083                   # 실물 CAD 조립 실측 (조립 후 재실측 권장)
# → 오프셋이 −0.12 에서 +0.0558 로 바뀜 = 공구축으로 175.8 mm 전진
```

sweep_m1013.py 의 `TCP = 0.12` 도 같은 방식으로 고칠 것.

### 작업대 배치는 제약이 아니다 — 재스윕 완료

`sweep_tcp.py` (본 세션 작성, 로컬 실행판). v5 원본이 없어 `v6_staging` 관절을 FK 로 되돌려 앵커 복원.
자기검증(`TCP=F+0.12`, `d=OFFSET` → 원본 재현) fail 0 / branch 0 통과.

| TCP | 1단계 통과 | 2단계 최선 d | min\|q5\| | J3 여유 |
|---|---|---|---|---|
| 60 mm | **54/54** | [+0.15, −0.15, +0.10] | 37.8° | 68.0° |
| 75 mm | **54/54** | 〃 | 38.6° | 69.2° |
| 90 mm | **54/54** | 〃 | 39.4° | 70.5° |

**격자 전 구간(x −0.25~+0.15, y ±0.15, z ±0.10)이 통과**했고 159 에피소드 전수 PASS.
원 스윕 winner 의 min|q5| 가 10.6° 였으므로 **손목 특이점 여유가 3.6배 늘었다.**
TCP 83 은 이 범위 안이라 안전.

> **결론: OFFSET 은 작업대 설치 후 실측해서 넣으면 된다.** 미리 정할 필요 없다.
> 원래도 winner(−0.25)가 아닌 +0.05 를 쓰고 있었다 = 밴드 안의 임의 선택이었다.
> 더 나은 방향은 **재렌더 시 OFFSET 랜덤화**로 정책을 작업대 위치에 둔감하게 만드는 것.

## 8. 손목캠 재정합 — 카메라를 기울여야 한다

### 현재 기하 (모델 검증 완료)

```
카메라 (−39.3, −45.3, 50) 플랜지 로컬, 측면 오프셋 60.0, forward = [0,0,1]
파지 시 큐브 = 플랜지 로컬 (0, 0, 258.8)
  → 이탈각 16.0°,  화면 세로 v = 0.84      (기록 실측 v = 0.86 → 모델 정확)
HFOV 60.3° · VFOV 47.1° (반각 30.15° / 23.54°)
```

### 재변환 후

| 조건 | 플랜지 → 큐브 | 이탈각 | 세로 위치 | |
|---|---|---|---|---|
| 현재 | 258.8 | 16.0° | 0.84 | ✅ |
| **TCP 83** | **83** | **61.2°** | 1.80 | ❌ **화면 밖** |

**어떤 위치로도 복원 불가** — 이탈각 16° 를 되찾으려면 카메라가 플랜지 뒤(z 음수, 로봇 내부)에 있어야 한다.

```
TCP 83, 측면 60 → 카메라 z = −126 mm   (불가)
TCP 83, 측면 45 → 카메라 z =  −74 mm   (불가)
TCP 83, 측면 30 → 카메라 z =  −22 mm   (불가)
```

→ **`forward_local = [0,0,1]` 폐기. 카메라 틸트 필요.**
후보: 위치 유지하고 시선을 큐브(0,0,83)로 → `forward_local ≈ (0.53, 0.61, 0.59)` (61.2° 틸트).
이 위치는 그리퍼 몸체 아래(z>45)라 시야가 가리지 않고, 핑거는 |y|≤15 이라 광선이 비켜간다.

**브래킷 카메라 패드가 경사면이 되어야 한다.** 확정 순서:
```
재변환 → Isaac 카메라 재정합(틸트 포함) → 카메라 선정 → 브래킷 확정
```

### 카메라 선정 기준 — 함정

파지 시 **카메라 → 큐브 거리가 65~90 mm**. **일반 USB 웹캠은 이 거리에서 초점이 안 맞는다**(최단 초점거리 보통 100~300 mm).

| 기준 | 값 |
|---|---|
| **최단 초점거리** | **≤ 65 mm** ← 가장 중요 |
| HFOV | ≈ 60° |
| 해상도·프레임 | 640×480 @ 30 fps |
| 인터페이스 | USB UVC (LeRobot 호환) |

→ **M12(S-mount) 보드캠 + 조절식 렌즈** 가 정답. 정면캠은 거리가 멀어 일반 웹캠으로 충분.

**플랜지 로컬 좌표로 조립**한 것. 원점 = 플랜지 면, +Z = 툴 방향, **단위 mm**.

```python
# link_6 밑에 변환 없이 붙는다. Isaac 은 m 단위이므로 스케일 0.001
add_reference_to_stage("/path/tool_assembly_flangelocal.stl", f"{link6_path}/tool_visual")
UsdGeom.Xformable(prim).AddScaleOp().Set(Gf.Vec3f(0.001, 0.001, 0.001))
```

**주의**: STL 은 **시각용**. 물리(collision)는 기존 박스 근사를 유지하는 편이 안정적이다.
메시 collision 은 볼록분해 비용이 크고 파지 접촉이 불안정해진다.

### 좌표 변환 (원본 STEP 에서 다시 만들 때)

```
그리퍼 (gx,gy,gz) → 플랜지 (gz, −gx, 12−gy)   : X −90° → Z −90° → +12z
핑거   (fx,fy,fz) → 플랜지 (fx, −fy, 53−fz)   : X 180° → +53z
어댑터 STEP z     → 플랜지 (12 − z)            : X 180° → +12z   (STEP 은 z0=그리퍼면)
그리퍼 블록 열림→닫힘 : 각 블록을 gz 로 ∓32 이동
```

### 클로킹 미정

+X 를 그리퍼 장축으로 뒀으나 **90° 단위 4가지**가 남는다. 조 열림 방향 · 손목캠 자리 · 튜브 방향이 걸린다.
**어댑터 가공에는 영향 없다**(부착 각도 문제). Isaac 씬과 IK 를 보고 확정할 것.

### 코드에 반드시 넣을 것 3가지

1. **채터링 방지** — 명령 30 Hz vs **MHF2 최대 60 c.p.m.(초당 1회)**. 히스테리시스 + 최소 유지시간
2. **`--grip-lead`** — 오토스위치 D-M9N 2개로 양방향 실측 후 선행 (30 Hz 에서 1.5~3프레임)
3. **관측값 정의** — 학습 데이터가 명령값이면 에코가 정합적. v5 그리퍼 채널 확인 후 결정
