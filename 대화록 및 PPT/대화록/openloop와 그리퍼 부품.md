## 요약

**정책 쪽**: ACT가 open-loop인 이유와 closed-loop 전환 경로를 정리했다. "그냥 궤적 재생 아닌가"라는 의문은 복사 베이스라인(5.07°) 대비 ACT(0.62°) 8배 차이로 반증했다. 다만 검증 세트가 없어 "외운 것"과 "배운 것"은 아직 구분되지 않는다.

**데이터 쪽**: 159개 파퀫을 직접 열어 파지 위치가 **204 × 125 mm에 분포**함을 확인했다(고정 위치가 아니었다 — 앞선 판단 정정). 카메라 투영 계산으로 큐브 위치가 정면캠에서 **138 px(화면 21.5%)** 폭으로 나타남을 확인했다.

**시뮬 쪽**: M1013 USD를 직접 열어 질량 32.86 kg·드라이브 게인을 확인했고, 관성텐서가 전부 0이며 현재 코드가 게인을 1e6으로 덮어써 사실상 kinematic replay임을 확인했다.

**하드웨어 쪽**: 보유 중인 SMC MHF2-16D2 + SY5120-5LOZ-01이 M1013에 사용 가능함을 카탈로그로 검증했다. 부품은 전부 재사용되고, 새로 만들 것은 전부 연결 금구다.

**연구 설계 쪽**: 산출물을 "점 하나(대체율)"에서 **"곡선(A·B·C 3계열)"**으로 바꿨다. 3×3 격자가 데이터로 성립하지 않음을 확인해 폐기했고, "굳이 OMX를 왜 넣는가"라는 근본 의문을 **실험 조건(A·C 대조군)으로 전환**했다. 이 연구가 N=1 사례임을 인정하고 주장 범위를 좁혔다.

# 1부 · 정책과 데이터

## 1. ACT 모델이 open-loop이라는 것의 의미

### 한 문장

> 정책이 실행 중에 아무것도 안 보고 있다. 시작할 때 녹화 영상을 한 번 통째로 먹여서 관절 궤적 전체를 뽑아 놓고, 로봇은 그 파일을 그냥 재생만 한다.

### 고리가 두 개 다 열려 있다

| | 지금 (open-loop) | 닫으면 (closed-loop) |
|---|---|---|
| ① 시각 입력 | OMX 실물 리그를 찍은 **녹화 영상** | Isaac 씬을 **실시간 렌더**한 화면 |
| ② 상태 입력 / 실행 | 정답 관절값을 넣어 궤적을 **미리 전부 계산** → 파일 재생 | 시뮬의 **현재 실제 관절값**을 읽어 매 스텝 다음 청크를 새로 질의 |

`replay_isaac.py`의 `--pred-npz` 방식이 정확히 이것이다.

### "0.62°"를 말할 때

매 프레임 정답을 다시 넣으며 잰 값이라 성능의 **상한**에 가깝다. 닫으면 오차가 누적된다.

- 증명된 것: 정책이 시연 궤적을 정확히 재현할 수 있다
- 증명 안 된 것: 정책이 상황에 대응할 수 있다

### 왜 일부러 open-loop인가

층을 하나씩 검증하려는 순서다. 궤적 층(6/8)과 정책 층(수렴)을 각각 확인해 두면, 닫았을 때 문제가 생겨도 원인이 시각 도메인 갭 하나로 좁혀진다.

### closed-loop 4단계

1. **배관 닫기** — Isaac 물리 스텝 → 2뷰 렌더 → 동일 전처리 → ACT 입력. 관절 상태는 시뮬 실측값
2. **도메인 갭 정량화** — 관측만 바꿔 A/B. 녹화 프레임 vs Isaac 렌더의 출력 차이
3. **갭이 크면 대응** — 재렌더 혼합학습 / 도메인 랜덤화 / 실기 파인튜닝 (측정 전에 결정하지 않는다)
4. **섭동 테스트** — 큐브를 ±2 cm 옮겨도 잡는가. 기준선은 정답 궤적 재생 6/8

## 2. "그냥 궤적 재생 아닌가" — 복사 베이스라인으로 반증

### 구조적으로 재생이 아니다

- ACT는 궤적을 저장하지 않는다. 고정된 신경망 가중치뿐이다
- 159개 시연이 서로 다 다르다 — 하나를 외운 게 아니라 공통 구조를 학습했다
- 입력이 (이미지 + 관절 상태)다. 재생은 입력을 안 본다

### 숫자로 반증된다

현재 데이터는 `state[t] = action[t-1]` 구조라, 관측을 안 보고 이전 상태를 그대로 밀기만 해도 어느 정도 맞는다. 그게 "그냥 따라하기"의 정량 기준선이다.

| chunk 내 위치 | 복사 베이스라인 MAE |
|---|---:|
| 1스텝 | 0.131° |
| 5스텝 | 0.647° |
| 25스텝 | 3.019° |
| 50스텝 | 5.443° |
| 100스텝 | 8.481° |
| **chunk 평균** | **5.069°** |

**ACT는 chunk 평균 0.62°. 약 8배 차이.** 관측을 실제로 쓰고 있다는 직접 증거다.

### 그럼에도 증명 안 된 것 — 검증 세트가 없다

159개를 전부 학습에 썼다. 0.62°는 **학습 데이터로 잰 값**이다. "배운 것"과 "외운 것"이 구분되지 않는다.

| 주장 | 상태 |
|---|---|
| "그냥 궤적 재생이다" | ❌ 반증됨 (5.07° vs 0.62°) |
| "159개 시연의 공통 구조를 학습했다" | ✅ 성립 |
| "새로운 상황에 대응한다" | ❌ 증명 안 됨 |

**해결**: 159개 사후 분할(예: 130/15/14) → 재학습 → held-out 평가. 재학습 3시간이면 된다.

## 3. 큐브 위치는 고정이 아니었다 — 실측 정정

앞서 "159개 시연이 전부 큐브가 같은 자리"라고 판단했으나 **틀렸다.** 159개 파퀫을 열어 FK로 파지/놓기 지점을 계산했다.

기준: 파지/놓기 전이 부근 TCP 최저점 (실제 큐브 접촉 지점), TCP = 0.12 m

| | PICK | PLACE |
|---|---|---|
| x | 703.6 ~ 907.4 mm (**204 mm**) | 683.5 ~ 874.4 mm (191 mm) |
| y | −325.1 ~ −200.5 mm (**125 mm**) | −111.7 ~ +43.8 mm (155 mm) |
| 표준편차 | x 34.2 / y 21.3 mm | x 42.2 / y 32.0 mm |
| 흩어진 영역 | **약 20 × 12.5 cm** | 약 19 × 15.5 cm |
| PICK↔PLACE 중심 거리 | 197 mm | |

수집 조건은 "로봇 기준 오른쪽 pick, 왼쪽 place"였고(y가 PICK에서 전부 음수), **그 안에서는 매번 다른 자리**였다.

*(z 절대값은 TCP=0.12가 잠정값이라 신뢰도가 낮다. 파지 시 접근이 거의 수직이라 xy는 신뢰할 만하다.)*

### 이것이 바꾸는 것

- **지금 못 잡는 건 여전히 확실** — open-loop이라 구조적으로 반응 불가
- **closed-loop을 붙이면 대응할 가능성이 있다** — 20 × 12.5 cm 범위의 위치 변화를 학습했으므로
- **held-out 에피소드 = 학습 때 안 본 큐브 위치** → 사후 분할 실험이 곧 위치 일반화 시험이 된다

## 4. 카메라가 큐브 위치를 담고 있는가 — 투영 계산

`cameras_v6match.json` 확정 파라미터로 159개 파지 지점을 화면에 투영했다.

### 정면캠 (world 고정, HFOV 69.9°, 640×480)

| | PICK | PLACE |
|---|---|---|
| 화면 안 | **159/159** | **159/159** |
| 가로 위치 범위 | u 179 ~ 317 px | u 404 ~ 571 px |
| 변화 폭 | **138 px (화면 21.5%)** | 168 px (26.2%) |
| 큐브 1 cm 이동 | 약 5.8 px | 약 6.8 px |

세 가지가 확인된다.

1. 35 mm 큐브가 화면에서 약 20 px인데 위치 변화 폭이 138 px — **큐브 크기의 약 7배**만큼 움직인다
2. **PICK(179~317)과 PLACE(404~571)가 화면에서 완전히 분리**된다. 겹치는 구간 0
3. 159개 전부 화면 안. 시야 밖으로 나간 에피소드 없음

### 손목캠 (link_6 부착, HFOV 60.3°)

| | 값 |
|---|---|
| 출발 시점 TCP ↔ 큐브 수평거리 | 평균 201 mm |
| HOME에서 큐브가 화면 안 | 4% |
| 처음 보이는 시점 | 접근 구간의 29% 지점 |
| 파지 전 구간 중 보이는 프레임 | 69% |
| 한 번도 안 보인 에피소드 | 0/40 |

역할이 나뉘어 있다 — **정면캠 = 거친 위치 파악, 손목캠 = 근접 정밀 정렬.**

### 출발 시점엔 눈밖에 없다

| 관절 | J1 | J2 | J3 | J4 | J5 | J6 |
|---|---|---|---|---|---|---|
| HOME 표준편차 | 0.79° | 1.13° | 0.70° | 2.58° | 4.15° | 1.88° |

팔 관절(J1~J3)이 사실상 동일하다. **큐브는 20 cm 범위로 움직이는데 시작 자세는 거의 같다** → 출발 시 올바른 방향으로 가려면 화면을 보는 수밖에 없다.

복사 베이스라인 결과와 합치면, 정책이 영상을 실제로 쓰고 있을 가능성이 매우 높다.

**추가 검증법**: 이미지 드롭아웃 ablation. 영상을 가리고 돌려서 성능이 무너지면 영상을 쓰는 것이고, 그대로면 관절 상태만 보고 평균 궤적을 그리는 것이다.

## 7. 좌표 변환의 기하 사슬 (전체)

변환은 **2단**이다. OMX를 M1013으로 직접 옮긴 게 아니라 **v5라는 중간 규약**을 거친다.

```
OMX 원본(v4) ──[1단: 강체 정렬]──▶ v5 (EE pose) ──[2단: 배치+보정+IK]──▶ v6-M1013 (관절)
```

v5는 TX90 base_link 프레임에 정렬된 EE pose 데이터셋이고, **이후 모든 로봇 전환의 공통 출발점**이다.

### 1단 · OMX 원본 → v5

**① 오일러 wrap 수정** — `rx`, `rz`가 ±π 경계에서 2π 점프. mod 2π 재매핑으로 연속화.

**② Umeyama 상사변환** — 작업 사각형 4코너를 대응점으로 최소제곱 추정

$$p_{v5} = s \cdot R_u \, p_{omx} + t_u$$

- OMX 4코너 `P1(+0.1119, −0.1596, +0.0574)` … `P4`, 사각형 **241 × 361 mm**
- 두 사각형 크기를 같게 잡았으므로 **s ≈ 1.0이 정상**
- 테이블 높이는 **그리퍼 개폐 전이 시점 z 평균(57.4 mm)** — 전 프레임 percentile은 HOME 자세에 오염돼 36 mm 어긋나고, 4코너가 동일 평면이라 **residual에 안 잡힌다**

**③ tool frame 90° 보정**

| | 접근축 (로컬) |
|---|---|
| OMX `end_effector_link` | +X |
| TX90 `tool0` | +Z |

$$R_{v5} = R_u \, R_{omx} \, R_y(+90°)$$

없으면 그리퍼가 옆으로 눕는다. 위치 residual로는 안 잡힌다.

**1단 결과: 자세 오차 28.9° → 1.8°**

### 2단 · v5 → M1013 관절 (`convert_v6_m1013.py`)

M1013과 TX90은 둘 다 바닥 설치 6축이고 base 프레임 규약(z-up)이 같아서 **회전 없이 평행이동만** 적용한다.

**④ 이동평균 평활** — 위치·오일러에 7프레임(`SMOOTH_W=7`). 오일러는 unwrap 후.

**⑤ 위치 평행이동**

$$p = p_{v5} + d, \qquad d = (+0.05,\ -0.15,\ +0.10)\ \text{m}$$

6×3×3 = 54 후보를 2단계 전수 채점해 확정 (1단계 53/54 통과 → 상위 5개를 159ep 재검증).

**⑥ 손목 45° 보정** — 사슬의 핵심

OMX 그리퍼 파지 접근축(플랜지 로컬):

$$\hat{d} = \frac{(0.705,\ -0.027,\ 0.708)}{\|\cdot\|}$$

ẑ를 d̂로 보내는 최소 회전(로드리게스):

$$A = I + \sin\theta\, K + (1-\cos\theta)K^2, \quad \theta = \arccos(\hat{z}\cdot\hat{d})$$
$$R' = R_{data} \, A$$

효과: $R'\hat{z} = R_{data}\hat{d}$ = **원래 OMX 그리퍼 빔이 향하던 방향**. 파지 순간 세계 수직(±11°)이었다.

| | 보정 전 | 보정 후 |
|---|---|---|
| `min\|q5\|` | 10.5° | **49.7°** |
| 프레임 간 최대 Δq | 5.1°/fr | **2.94°/fr** |

**⑦ TCP 후퇴**

$$p_{flange} = p - R' [0, 0, L]^\top, \qquad L = 0.12\ \text{m}$$

OMX가 4축이라 기울여 접근(집기 시점 틸트 중앙값 44°)했고, TCP를 무시하면 **수평 오차 중앙값 84 mm**가 난다. "테이블을 12 cm 내리면" 으로는 해결 안 되는 이유.

**⑧ 오프라인 IK — 적응 감쇠 DLS**

$$q_{k+1} = q_k + J^\dagger_{\lambda}\, e, \qquad e = [\,p_{tgt}-p_{cur};\ \mathrm{rotvec}(R_{tgt}R_{cur}^\top)\,]$$

- **6 Hz 앵커**(`ANCHOR_K=5`, 끝 프레임 포함)에서만 IK
- **직전 해를 시드**로 → 해가 연속
- j4·j6를 0 쪽으로 **3° 넛지**
- **2π 접기** 후 시드 대비 **90° 초과는 브랜치로 거부**
- 실패 시 섭동/난수 시드 재시도 (seed=12345 고정)

> **전 에피소드가 HOME 시드를 공유해야 한다.** 에피소드마다 브랜치를 따로 고르면 j5가 +65°/−253°로 갈려 **정책이 같은 관측에 다른 라벨**을 본다.

**⑨ 30 Hz 보간** — 앵커 사이 관절 선형 보간. `state[t] = action[t-1]` (완전 추종 가정).

### 프레임별 한 줄 요약

```
R_flange = Euler_xyz_extrinsic(rx, ry, rz) @ A       # A = 45° 상쇄 회전
p_flange = (p_v5 + d) − R_flange @ [0, 0, L]         # d = 배치 오프셋, L = TCP
q        = IK_DLS(p_flange, R_flange, seed=직전 해)
```

### 검증 (159 에피소드 전수)

| 항목 | 값 |
|---|---|
| IK 성공 | **159/159**, 실패 0 · 브랜치 0 |
| 변환 소요 | **5.7초** |
| FK 역검증 | 위치 최대 **4.85 mm** · 자세 **1.03°** |
| IK 셀프테스트 | 랜덤 1000회 전부 수렴, ≤ 0.1 mm |
| 프레임 간 최대 Δq | **2.94°/fr** |
| 손목 특이점 여유 | **49.7°** · 관절 리밋 여유 **67.6°**(J3) |

### 설계상 특징

- **회전 3회 · 평행이동 2회.** M1013 전환에서 새로 들어간 건 `d`와 `A` 둘뿐 — 로봇을 바꿔도 v5 아래만 갈아끼우면 된다
- **데이터는 한 번도 수정하지 않았다.** v5 원본은 그대로, 번역 규칙만 바꿨다. 45° 보정도 데이터가 아니라 IK 목표 자세를 바꾼 것

> ⚠️ 8/19 스윕에서 "작업대를 TX90과 같은 방향으로 놓으면 손목 특이점에 붙으니 yaw 90° 돌려야 한다"는 결론이 있었으나, 현재 코드는 평행이동만 적용하고 yaw 회전이 없다. 그 결론은 **45° 보정 이전**의 것이고 보정으로 대체된 것으로 보인다. 실물 작업대 설치 전 확인 필요.

## 8. 45° 보정의 진짜 원인 — 그리퍼 장착 형상

`convert_v6_m1013.py:84`

```python
R = euler_xyz_extrinsic_to_R(*ac_s[t, 3:6]) @ CORR
#   └─ ① 오일러 → 회전행렬 (무손실)      └─ ② 45° 보정 (원인)
```

**OMX는 그리퍼가 플랜지에서 45° 꺾여 달린 로봇**이었다. 사람이 손목을 기울여야 그 꺾인 빔이 아래를 향했다. 영상에서 "가로로 잡는 것처럼" 보인 건 손목이 기울어진 것이고, 그리퍼 빔은 아래를 보고 있었다.

| 시점 | 손목 자세 | 그리퍼 장착 | 결과 |
|---|---|---|---|
| OMX 실물 | 45° 기울임 | **꺾인** 어태치먼트 | 빔이 아래 → 성공 |
| 보정 전 sim | 데이터 그대로 45° 기울임 | **일자** | 45° 기울어 진입 → 불도저 → 12번 실패 |
| 보정 후 sim | `@ CORR`로 수직 | **일자** | 빔이 아래 → 성공 |

**발표용 문장**

> 회전 표현 문제가 아니라 그리퍼 장착 형상 전제가 달랐던 것입니다. OMX는 45° 꺾인 어태치먼트라 사람이 손목을 기울여 시연했는데, M1013에는 일자로 달 계획이라 데이터의 손목 자세를 그대로 쓰면 그리퍼가 기울어진 채 진입합니다. 그래서 IK 목표 자세에 45°를 상쇄하는 회전을 곱해서 일자 그리퍼로 OMX와 같은 접근 방향을 재현했습니다.

| 파라미터 | 신뢰도 |
|---|---|

## 10. 서보 게인이란 (쉬운 설명)

모터는 순간이동을 못 한다. 힘만 낸다. 그래서 **목표 지점에 고무줄로 묶어 끌어당긴다.**

- **kp (stiffness)** = 고무줄 세기. `토크 = kp × (목표각 − 현재각)`
- **kd (damping)** = 꿀 속 저항. `토크 = −kd × 각속도`. 없으면 목표를 지나쳐 진동
- **maxForce** = 모터 최대 토크. M1013 J1·J2 346 Nm, 손목 3축 50 Nm

현관문 도어클로저와 같다 — 스프링이 당기고(kp), 유압이 쾅 닫히지 않게 한다(kd).

| | kp 낮음 | kp 적당 | kp 높음 |
|---|---|---|---|
| kd 낮음 | 처지고 흔들림 | 오버슛 후 진동 | 고주파 떨림 |
| kd 적당 | 느리고 처짐 | **정상** | 뻣뻣하지만 정확 |
| kd 높음 | 안 움직임 | 굼뜸 | 매우 굼뜸 |

kp = 100만이면 고무줄이 아니라 **강철봉으로 용접해 놓은 것**이다.

실기에서는 두산이 공장에서 튜닝한 게인을 보통 못 바꾼다. **시뮬 게인을 실기에 맞추는 것 = 시뮬이 실기를 예측하게 만드는 것.**

## 11. Isaac 검증의 범위 — 세 화면, 구도 vs 외관

화면의 차이에는 축이 두 개다.

| 축 | 뜻 | 맞출 수 있나 |
|---|---|---|
| **구도** | 카메라 위치·방향·화각 | ✅ 설정하면 됨 |
| **외관** | 화면에 실제로 뭐가 어떻게 찍혀 있는가 (로봇 모양, 재질, 실사/CG) | ❌ 설정으로 안 됨 |

| | 구도 | 외관 |
|---|---|---|
| **① OMX 학습 영상** | OMX 리그 | **OMX 실물 팔 + 실사** |
| **② Isaac 렌더** | ①에 맞춤 (8/24 완료) | **M1013 렌더 팔 + CG** |
| **③ 실물 M1013** | 전략에 따라 자유 | **M1013 실물 팔 + 실사** |

**② 와 ③ 은 ① 과 서로 다른 방식으로 다르다.** 그래서 "Isaac에서 잘 되면 실물에서도 잘 된다"가 성립하지 않는다.

### 계획마다 갭이 다른 곳에 있다

```
지금 ACT :  OMX 실사 이미지  →  M1013 관절      [임베디먼트 갭]
설계서   :  Isaac 렌더 M1013 →  M1013 관절      [sim-to-real 갭]
```

**설계서는 갭을 없애는 게 아니라 바꾸는 것이다.**

**바꾸는 결정적 이유**: OMX 실사 영상으로는 색·위치 조합을 만들 수 없다. 찍힌 게 전부다. Isaac에서는 코드로 무한히 생성된다.

| 갭 | 대응 |
|---|---|
| 임베디먼트 갭 (팔 모양) | 어려움 — Mirage / RoVi-Aug 같은 특수 기법 |
| **sim-to-real 갭 (CG vs 실사)** | **표준 대응법 존재** — 도메인 랜덤화 + 실기 소량 fine-tune |

→ 도메인 랜덤화는 선택이 아니라 필수다. 렌더로 갈아탄 순간 sim-to-real 갭을 떠안았다.

### Isaac에서 되는 것 / 안 되는 것

**되는 것**: 색상 구분 원리 검증 · 위치 일반화 · 조합 필요량 · 롤아웃 성공률 자동 채점 · closed-loop 배관 · 코드 리허설
**안 되는 것**: 실사 이미지 갭의 크기

> **Isaac은 "될 것"을 증명하진 못하지만 "안 될 것"을 싸게 걸러낸다.**

Isaac에서 색상 구분이나 위치 일반화가 안 되면 실기에서는 거의 확실히 안 된다. 그걸 실기 200개 찍고 나서 알면 4주를 날린다.

```
════════════════  ← TX90 플랜지 (은색 링, ↑ 마킹) ★ 여기가 손바닥
  원기둥 스페이서    ← 커스텀 ①
  사각 플레이트      ← 커스텀 ② (약 50 mm 정사각, 볼트 머리 ø9~10 → M6 유력)
  MHF2-16D2
  핑거 어태치먼트    ← 커스텀 ③ (칼날형, 얇은 판재용)
```

**사각 판의 볼트는 플랜지가 아니라 원기둥에 체결된다.** 판이 50 mm 정사각인데 PCD 50이면 볼트 중심이 변에 걸리므로 기하학적으로 불가능 — PCD는 40 mm 근처로 추정된다(ISO 9409-1에 PCD 40 / 외경 50 / M6 조합 존재). **M1013(PCD 50)과 불일치.**

### 새로 만들어야 하는 것

**어댑터 플레이트 — AL6061 8~10 mm 가공** (원기둥 + 사각 판을 한 장으로 통합)

| 면 | 가공 |
|---|---|
| 로봇 쪽 | ø6.6 관통홀 ×4 (PCD 50) · ø31.5 h7 스피곳 돌출 4~5 · ø6 h7 핀 홀 |
| 그리퍼 쪽 | ø5.5 관통홀 ×4 (36 등간격) · ø4 h7 핀 홀 ×2 |

3D 프린팅 금지 — 크리프로 TCP가 흐른다.

**핑거 어태치먼트 — 3D 프린팅**: 핑거당 4-M4 깊이 4 + ø3 h7 핀. 닫힘 갭 33~34 mm, 돌출 **25~35 mm**(짧을수록 파지력·정밀도 유리), TPU 패드.

**밸브 브래킷** — TX90 팔 형상 + 내장 에어 전제라 재설계. 자바라 여유 루프 방식은 차용.

## 16. 곡선 실험 설계 — A · B · C

산출물을 **점 하나 → 곡선**으로 바꿨다.

| 계열 | OMX 층 | 실기 층 | 무엇을 가르는가 |
|---|---|---|---|
| **A1~A3** | 없음 | 10 / 25 / 50 | 기준선. **"그냥 파인튜닝하면 되지 않나"가 곧 A** |
| **B1~B3** | **OMX 200** | 10 / 25 / 50 | — |
| **C3** | **스크립트 궤적 200** | 50 | 같은 씬·같은 렌더, 궤적만 모션플래너 생성 |

```
B − A  =  중간층 전체의 기여
B − C  =  사람 시연이라서 생기는 고유 기여
C − A  =  궤적·씬 다양성만으로 얻는 기여
```

**추가 수집 0.** 실기 50개를 한 번 수집하고 10/25/50은 같은 세트의 부분집합. B 계열은 OMX 200 체크포인트 하나를 공유 → **OMX 학습 1회 + 이어학습 7회.**

### 공정성 3원칙

① A·B·C 모두 held-out 최고점에서 조기종료 (E6를 일부러 못 하게 만들면 자기기만)
② 평가 세트 완전 동일
③ 실기 부분집합은 같은 에피소드

### 학습 절차

좌표 변환은 **전부 오프라인 데이터 준비 단계**에서 끝난다. 학습기가 보는 형식은 A·B·C가 동일하다 → **성능 차이를 데이터 기여로만 귀속**할 수 있다.

```
B   base(고정) ──[층2 200개]──▶ 중간 체크포인트 ──[층3]──▶ 최종   (2단계)
A   base(고정) ──[층3]──▶ 최종                                   (1단계)
```

순차(2단계)를 권하는 이유: **1단계를 실기 도착 전에 미리 끝낼 수 있다.** 혼합(co-training)은 도착 후 전체 재학습이 필요하고, 200:40 비율이라 실기가 묻힌다. 까먹음 대비로 낮은 학습률 + 소량 rehearsal.

## 17. 네 가지 결과 시나리오 — 결과를 가정하지 않는다

| 시나리오 | 곡선 모양 | 의미 | 다음 행동 |
|---|---|---|---|
| **① 대체** | B가 위, 실기 늘수록 격차 좁아짐 | OMX가 실기를 대신함 | 실기 소량으로 종료 |
| **② 보완** | B가 위, 격차 유지 | OMX가 실기로는 못 얻는 걸 줌 | 실기 늘려도 OMX 유지 |
| **③ 무기여** | 두 곡선 겹침 | OMX가 일하지 않음 | 실기만 수집, 층2 재검토 |
| **④ 음의 전이** | **B가 아래** | CG 특징 고착이 실사 학습을 방해 | 랜덤화 강화 또는 **층2 폐기** |

**④는 실재하는 가능성이다.** Isaac 렌더로 먼저 학습하면 모델이 CG 특유의 것(고정 텍스처, 균일 조명, 잡음 없는 엣지)에 고착될 수 있고, 그 상태에서 실사로 이어학습하면 실사만으로 하는 것보다 나쁠 수 있다(negative transfer).

**②가 나오면 오히려 더 흥미롭다** — "대체율"보다 "보완 가치"가 주장하기 좋은 결과다.

## 18. 데이터가 강제한 설계 변경

### ① 3×3 격자는 성립하지 않는다

159개 파지 위치를 격자에 넣어봤다.

| 격자 | 셀당 개수 | 문제 |
|---|---|---|
| 등간격 | **0 ~ 84개** (중앙 셀에 53%) | 빈 셀 1개 |
| 등분위 | 8 ~ 26개 | 중앙 셀 폭 18 mm — 물리적으로 무의미 |

→ **격자 이산화 폐기.** 위치는 연속으로 다루고, 학습에 쓰지 않은 위치에서의 성공률로 일반화를 평가한다.

→ 따라서 **"3색 × 9셀 = 27조합 × 6~8ep = 160~216개 필요"라는 논거도 폐기.** 필요량은 미지수이고, 그걸 재는 게 연구다.

### ② 색상 조건은 합성해야 하고, 함정이 있다

OMX 159개는 **단색 큐브 하나**뿐이다. 색상 조건은 Isaac 재렌더 시 입힌다.

> ⚠️ **장면에 큐브가 하나면 무의미하다.** 지시된 색 = 유일한 큐브가 되어버려, 모델이 "색을 보고 고르는 법"을 배우지 않는다. 언어 입력이 상수가 된다.

→ **방해 큐브를 다른 색으로 함께 배치해야 한다.** 타깃이 아닌 위치에 1~2개. 이때 비로소 언어 입력이 일을 한다.

### ③ 도메인 랜덤화는 필수

조명·텍스처·배경·카메라 지터. 목적은 사실성이 아니라 **시뮬 전용 특징 고착 방지**. 씬이 고정색이면 "RGB(0.1,0.2,0.9) 픽셀 덩어리"를 학습하고, 그러면 실기 fine-tune 후 sim 200개가 남긴 게 없어진다.

### ④ TCP 트랙 분리

Isaac 트랙은 **현재 TCP 0.12로 그대로 진행**한다. 어태치먼트 제작을 기다리지 않는다. TCP 확정(120 → 약 70 mm 예상)은 하드웨어 트랙에서 나중에 합류시킨다.

## 19. 근본 의문 — 굳이 OMX를 왜 넣는가

가장 큰 반박이고, 아직 답이 없다.

**① base는 이미 같은 급 로봇 데이터로 학습됐다** — `smolvla_base` = SO-100/101 소형 암 실사 데이터. **OMX도 같은 급 소형 암**이라 한계 기여일 수 있다.

**② 재렌더하면 OMX 이미지는 사라진다** — 남는 건 궤적뿐. 이미지는 전부 Isaac 렌더, 액션도 IK로 만든 M1013 관절이다. **OMX 관절도 아니다.**

**③ 그러면 모션플래너 궤적과 무엇이 다른가** — "사람이 시연했다"는 것 말고 남는 차이가 없다.

### 답 — 의문을 실험 조건으로 만들었다

- **A 계열**이 정확히 "그냥 파인튜닝하면 되지 않나"다. A가 이기면 OMX 층은 불필요하다는 결론
- **C 계열**이 "사람 시연이어야 하는가"를 직접 가른다

> **"OMX가 필요하다"를 주장하지 않는다. A·B·C를 나란히 돌려서 필요한지 아닌지를 결과가 말하게 한다.**

### 아직 답이 없는 나머지 전제

| 전제 | 지금 상태 | 언제 답하나 |
|---|---|---|
| **결승선** | Isaac 성공률인가 실물 동작인가 | **결정 필요** |
| 실사 갭 크기 | 실기 50개로 메워진다는 건 가정 | 실기 도착 후에만 |
| **학습 시간** | SmolVLA 1회 15~40시간 추정, **실측 없음** | **1주차** |
| 평가 지표 전환 | 롤아웃 자동 채점기 미구축 | **1주차** |

## 20. 연구 범위와 한계 — N = 1 사례

### 국한되는 것

**① 로봇 쌍 1개** — OMX(4축) → M1013(6축). OMX가 4축이라 위치를 맞추면 자세가 따라 결정되고(파지 틸트 중앙값 44°), **시연의 자세 정보 자체가 이미 제약된 값**이다.

**② 태스크 1종** — 손끝 궤적으로 기술되는 것만. 삽입·조립·닦기는 힘 제어 데이터가 없어 불가.

**③ 대체율 수치는 이 조합 한정** — 로봇 쌍·태스크·카메라 구성이 바뀌면 값도 바뀐다.

### 혼동하지 말아야 할 것

- **코드의 이식성 ≠ 연구 결과의 일반성.** TX2-90 → M1013 하루 전환은 파이프라인이 잘 짜였다는 엔지니어링 증거이지, 대체율이 다른 쌍에서도 같다는 근거가 아니다
- **질문의 일반성 ≠ 답의 일반성.** 우리가 내는 것은 점 하나다. 선을 그으려면 로봇 쌍 3~4개 · 태스크 복수가 필요하다

### 그럼에도 남는 가치

1. **엔지니어링 실적** — 데이터 변환 · 배치 스윕 · 자체 IK · 시뮬 검증 · 정책 학습 · 실기 이관 전 과정을 자립 구축
2. **실무 의사결정 근거** — "실기를 몇 개 찍어야 하는가"에 답한다
3. **데이터가 적은 구간의 한 점** — 문헌(Mirage · RoVi-Aug)은 유사 급 전이 위주. 4축 데스크톱 → 6축 1.3 m 산업용은 흔치 않은 조합

**주장 범위**: "이 방법이 일반적으로 통한다"가 아니라 **"이 조합·이 태스크에서 대체율이 이만큼이었다"**까지.

### 안심할 것

**어느 방향으로 가도 1~2주차 작업은 그대로 쓰인다** — 롤아웃 채점기, Isaac 씬 확장 + 도메인 랜덤화, closed-loop 배관, 그리퍼 조립·TCP. **방향 결정을 3주차까지 미뤄도 낭비가 없다.**

### OMX를 꼭 뺄 필요는 없다

의문은 "OMX를 데이터로 쓰는 것"이 아니라 **"OMX 전이 자체를 연구 주제로 삼는 것"**에 있다. 방향을 바꿔도 OMX 159개를 학습 데이터로 쓸 수 있고, 그때 OMX는 **주제가 아니라 재료**라서 "왜 OMX냐"는 질문이 안 나온다.

| # | 제목 | 성격 |
|---|---|---|
| ① | 「저비용 소형 매니퓰레이터 시연은 산업용 로봇 실기 데이터를 얼마나 대신하는가」 | 직관적. "얼마나"라는 양적 주장이라 N=1에서 공격받기 쉬움 |
| **②** ⭐ | **「VLA 전이학습에서 소형 로봇 시연 데이터의 기여 분해 — 궤적 다양성과 시연 고유성의 분리」** | **지금 설계(A·B·C)와 정확히 일치. "왜 OMX냐"가 제목 안에서 해소됨** |
| ③ | 「4축 소형 암에서 6축 산업용 협동로봇으로의 모방학습 전이 — 파이프라인 구축과 데이터 대체율 사례 연구」 | 가장 정직. 현장실습 보고·대학원 지원용 |
| ④ | 「사전학습된 VLA에 중간 도메인 데이터를 넣는 것이 도움이 되는가」 | 부정적 결과까지 포용 |

**② 추천 이유**: (1) "굳이 OMX를 왜"가 주제 자체로 흡수됨 (2) 어떤 결과가 나와도 제목이 유효(분해가 결과) (3) C 계열을 넣은 설계에서만 가능한 제목.

### 결과에 따라 최종 제목이 갈린다

| 결과 | 최종 제목 방향 |
|---|---|
| B ≫ A, B > C | "사람 시연이 실기 데이터를 대체한다" |
| **B ≈ C > A** | **"궤적 다양성이면 충분하다 — 사람 시연은 불필요"** ← 실용적 함의가 큼 |
| B ≈ A | "사전학습된 VLA에는 중간층이 기여하지 않는다" |
| B < A | "합성 중간층의 음의 전이" |

**결과 전에 제목을 확정하면 결과를 제목에 맞추게 된다.** 지금은 working title로 두고 진행할 것.

## 23. 실행 계획 — 두 트랙 병행

```
소프트웨어  [채점기 + 학습시간 실측] → [재렌더 200] → [학습 7회] → [곡선 분석] ┐
                                                                              ├→ 합류
하드웨어    [벤치 배관] → [어태치먼트·어댑터] → [조립·파지] → [TCP 실측]      ┘
                                                                    실기 50개 수집
                                                                    → A/B/C 재현
                                                                    → 최종 곡선
```

| 주 | 반드시 끝내야 하는 것 | 이유 — 무엇이 막히는가 |
|---|---|---|
| **1** | 롤아웃 자동 채점기 · **SmolVLA 1회 학습시간 실측** · 다색+방해 큐브 씬 | 채점기 없으면 어떤 실험도 숫자가 안 나온다. 학습시간 없이는 7회가 4주에 들어가는지 모른다 |
| **2** | 재렌더 200 (색 합성 + 방해 큐브 + 도메인 랜덤화) · 실기대역 50개 | 3주차 학습의 입력 |
| **3** | OMX 200 학습 1회 → 이어학습 7회 → 롤아웃 평가 | 예산 초과 시 실기 점을 3개 → 2개(10·50)로 축소 |
| **4** | 곡선 분석 · v7 수집 스크립트 · 실기 절차서 | 도착 당일 바로 수집에 들어가기 위한 도구 |

### 최대 위험 — 학습 시간

SmolVLA 1회가 15~40시간이면 7회는 4주를 넘긴다. **1주차에 실측하지 않으면 3주차에 터진다.**

대응(효과 큰 순): `freeze_vision_encoder=True` · 스텝을 데이터 크기에 맞춤(5~10 epoch) · 실기 점 3→2 · **곡선은 ACT로, 색상 조건만 SmolVLA로**(ACT는 2.8시간)

측정법: 1000 스텝만 돌려 `update_s`를 보고 외삽 → 30분이면 나온다.

## 24. 발표대본 정정 사항

- **Q8의 "그리퍼 길이(현재 150 mm 가정)"** → 실제 코드는 `TCP = 0.12` (**120 mm**). 대본이 틀렸다
- 그리퍼는 보유 자산으로 확정 가능 → 논의요청 1순위를 닫고 작업대·카메라에 시간을 쓸 것
- **"6/8 성공"을 실기 성공률 예측으로 말하지 말 것** — kp=1e6이라 물리가 사실상 무력화된 상태의 기하 검증이다
- 발표에서 **연구 방향 후보 목록(21장)을 올리고 의견을 구하는 것**이 기존 논의요청 4가지보다 우선순위가 높다
